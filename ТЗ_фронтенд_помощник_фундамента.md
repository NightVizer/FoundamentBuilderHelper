# ТЗ — Фронтенд MVP «Помощник проектировщика фундамента»

Версия: 1.0 · 26.09.2026
Статус: согласовано (гриллинг-сессия). Один открытый пункт: визуальный дизайн — будет доработан по скриншоту-референсу.

---

## 1. Что делает MVP

Пользователь вводит 8 упрощённых характеристик (геология → здание → условия). Система через модель **Jev** мгновенно выдаёт **процент пригодности** каждого из 4 типов фундамента. Фронт показывает **топ-3**: победителя в центре и две альтернативы под ним. Вторая LLM (deepseek и т.п.) догружает тексты «плюсы / минусы / чем лучше альтернатив».

MVP **не** делает: нормативный расчёт, стоимость, трудозатраты, отчёт, дисклеймеры. Это система предварительного выбора, а не «цифровой инженер».

---

## 2. Поток данных

```
Форма (8 полей)
   │  клик «Рассчитать»
   ▼
POST /api/foundation/recommend ──► Backend ──► ОДИН вызов Jev (4 вопроса Noul)
   │                                              ~0,1–0,3 сек
   ▼
Фронт сразу рисует: топ-3 карточки с процентами (места текстов — спиннеры)
   │
   ▼
POST /api/foundation/explain ──► Backend ──► Вторая LLM, ОДИН запрос
   │                              (все 3 текстовых блока сразу)
   ▼
Спиннеры сменяются текстами
```

Ключевые решения:
- **Проценты — только от Jev** (никакого rule-engine-скоринга на экране).
- Оценки всех 4 типов приходят **одним вызовом Jev** («вместе», а не параллельными вызовами).
- Тексты для всех 3 карточек — **одним запросом** ко второй LLM.
- Бэкенд/Jev отдаёт **все 4 типа**, топ-3 отбирает **фронт** (сортировка по убыванию).
- Оценки независимые, **не нормализуются** к сумме 100.

---

## 3. Экран 1 — Ввод

Заголовок страницы: **«Помощник проектировщика фундамента»**

Названия полей — единые для Frontend и Backend (API-имя из документа-плана).

### Секция «Геология»

| Поле | API-поле | Контрол | Варианты |
|---|---|---|---|
| Тип грунта | `soil_type` | селект | Песок / Супесь / Суглинок / Глина / Насыпной грунт (`sand`, `sandy_loam`, `loam`, `clay`, `fill`) |
| Несущая способность | `bearing_capacity` | селект | Низкая / Средняя / Высокая (`low`, `medium`, `high`) |
| Уровень грунтовых вод | `groundwater_level` | селект | Низкий / Средний / Высокий (`low`, `medium`, `high`) |

### Секция «Здание»

| Поле | API-поле | Контрол | Варианты |
|---|---|---|---|
| Этажность | `floors` | **числовой ввод вручную** | целое ≥ 1 |
| Площадь здания | `building_area_m2` | число + суффикс «м²» | > 0 |
| Материал стен | `wall_material` | селект | Дерево / Газобетон / Кирпич / Железобетон (`wood`, `aerated_concrete`, `brick`, `reinforced_concrete`) |

### Секция «Условия»

| Поле | API-поле | Контрол | Варианты |
|---|---|---|---|
| Регион | `region` | селект | Москва / Красноярский край / Свердловская область (`moscow`, `krasnoyarsk_krai`, `sverdlovsk_oblast`) |
| Сейсмичность | `seismicity` | селект | 0–6 баллов / 7 баллов / 8+ баллов (`0-6`, `7`, `8+`) — ручной выбор, не автоподстановка |

### Поведение

- Форма стартует **пустой** (префилл — план-максимум).
- Кнопка **«Рассчитать»**: неактивна (серая), пока не заполнены **все** поля; без отдельной валидации с красными сообщениями.
- Клик по активной кнопке → переход на экран 2.
- Состояние **не сохраняется** (никаких localStorage/URL-параметров): вернулся назад — заполняй заново.

## 4. Экран 2 — Результаты

Заголовок страницы: **«Результаты подбора»**

### Карточка победителя (по центру)

Сверху вниз:
1. Плашка: **«Наиболее подходящий вариант»**
2. Название: «Свайный фундамент» и т.п.
3. **Маленькое радиальное кольцо** (одинакового размера с кольцами альтернатив) с процентом внутри: **«87%»**
4. Развёрнутый текстовый блок (от второй LLM):
   - **Плюсы**
   - **Минусы**
   - Абзац **«чем лучше альтернатив в ваших условиях»**

### Альтернативы (под победителем)

- **Две карточки в ряд по горизонтали**, слева направо по убыванию процента (2-е и 3-е место).
- В каждой: название, маленькое радиальное кольцо с «74%» / «51%», текстовый блок **покороче, чем у победителя, но не две строчки** (несколько плюсов/минусов, без блока «чем лучше других»).

### Динамика загрузки

- Проценты и названия карточек появляются **мгновенно** (ответ `/recommend` быстрый, достаточно спиннера на кнопке перед переходом).
- На местах текстовых блоков крутятся **спиннеры-кружочки**; после ответа `/explain` все тексты подставляются **разом**.

### Прочее

- Кнопка **«Новый расчёт»** (сверху справа) → возврат на пустую форму.
- **Нет** на этом экране: стоимости, трудозатрат, дисклеймера/предупреждений, отчёта, переключателя региона.

## 5. API-контракт

### POST /api/foundation/recommend

Запрос:

```json
{
  "soil_type": "loam",
  "bearing_capacity": "medium",
  "groundwater_level": "high",
  "floors": 3,
  "building_area_m2": 450,
  "wall_material": "brick",
  "region": "krasnoyarsk_krai",
  "seismicity": "7"
}
```

Ответ — **все 4 типа**, фронт сам берёт топ-3:

```json
{
  "scores": {
    "pile": 87,
    "slab": 74,
    "strip": 51,
    "column": 23
  }
}
```

- Значения: целые 0–100, независимые, не нормализуются.
- Фронт: сортировка по убыванию → победитель + 2 альтернативы.

### POST /api/foundation/explain

Запрос (фронт передаёт исходные данные + выбранный топ-3 с оценками):

```json
{
  "input": { "...": "те же 8 полей" },
  "top3": [
    { "type": "pile", "score": 87 },
    { "type": "slab", "score": 74 },
    { "type": "strip", "score": 51 }
  ]
}
```

Ответ — все тексты одним пакетом:

```json
{
  "explanations": {
    "pile":   { "pros": ["..."], "cons": ["..."], "vs_others": "..." },
    "slab":   { "pros": ["..."], "cons": ["..."] },
    "strip":  { "pros": ["..."], "cons": ["..."] }
  }
}
```

- `vs_others` — только у победителя.
- LLM **не имеет права** менять типы/score и придумывать параметры, которых не было на входе (требование к промпту на бэкенде).

## 6. Интеграция Jev (для бэкендщика)

- Endpoint: `POST https://api.typesafe.ai/v1/systemone` (Bearer auth), тело `{model, state, questions}` — карта именованных вопросов, ответы приходят под теми же ключами.
- **Один вызов = 4 вопроса Noul** (по одному на тип фундамента): «Подходит ли {тип} фундамент для данных условий?» → ответ 0–1 (вероятность) → ×100 → процент для фронта.
- Почему Noul: даёт честный непрерывный «процент пригодности», ровно то, что показывает кольцо. Примитив Score — рубрика 0–9, потребовал бы масштабирования.
- Модели: `jev-latest` (= `jev-1.13.0`). SDK: Python `pip install typesafe-sdk`, TS `npm install @typesafe-ai/sdk`.
- Цена: ~$0,042/Mtok на вход, вывод бесплатный; на старте $5 кредитом. Латентность ~0,1–0,3 сек на вызов. Лимитов на число вопросов в вызове нет.
- **Jev не генерирует текст вообще** — только типизированные значения. Тексты — строго вторая LLM.

---

## 7. Обработка ошибок

- Любая ошибка (`/recommend` или `/explain` недоступны, невалидный ответ) → единый экран: **«Произошла ошибка, перезагрузите страницу»**. Без retry-кнопок, без частичных фолбэков.

## 8. Стек

- React + TypeScript + Vite + Tailwind CSS
- Маршрутизация: два экрана (ввод → результаты), переход по клику «Рассчитать»
- Фронт пишется сразу под живой бэкенд (mock-режима нет)
- Визуальный стиль: светлая тема, «инженерный» — финализируется по скриншоту-референсу (единственный открытый пункт)

---

## 9. Явно НЕ входит в MVP

- Стоимость и трудозатраты (в т.ч. региональные цены)
- Отчёт / ТЭО / скачивание
- Дисклеймер «предварительное решение»
- Сохранение состояния, deep-links, мобильная адаптация
- Пятый (комбинированный) тип фундамента — всегда ровно 4 типа
- Нормативные расчёты (глубина заложения, сечение, армирование и т.п.)

## 10. План-максимум (в порядке добавления)

1. Переключатель региона прямо на экране результата с живым пересчётом (wow-демо региональных цен)

4. Скачиваемый отчёт (кнопка под выводами о фундаментах)
5. Префилл формы демо-примером
6. Автоподстановка сейсмичности от региона
7. Визуальный дизайн по скриншоту-референсу

## 11. Журнал решений (кратко)

| Решение | Выбор |
|---|---|
| Источник процента | Jev, не rule engine |
| Все оценки одним вызовом | да (вопросы в одном запросе) |
| Тексты одной LLM-запросом | да, все 3 блока сразу |
| Сколько показывать | топ-3 из 4, отбор на фронте |
| Формат оценки | «87%» внутри кольца, без нормализации |
| Кольцо | маленькое, одинаковое у победителя и альтернатив |
| Победитель | по центру, плашка «Наиболее подходящий вариант», блок «чем лучше альтернатив» |
| Альтернативы | 2 карточки в ряд, тексты покороче |
| Кнопка «Рассчитать» | есть, неактивна до полного заполнения |
| Этажность | ручной числовой ввод |
| Регионы MVP | Москва, Красноярский край, Свердловская область |
| Сейсмичность | ручной селект 0–6 / 7 / 8+ |
| Ошибки | «перезагрузите страницу» |
| Заголовок экрана 2 | «Результаты подбора» |
